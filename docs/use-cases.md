## 1. Ignore values generated by the system

Ids, timestamps and version stamps are set by the code under test or the database, so you cannot know them in advance. Ignore them:

```csharp
var actual = CustomerService.Register("Jacob", "jacob@example.com", "Hanoi");

var expected = new Customer
{
    Name = "Jacob",
    Email = "jacob@example.com",
    ShippingAddress = new Address { Street = "1 Main St", City = "Hanoi", Country = "VN" },
};

DeepAssert.Equal(expected, actual, o => o.Ignore(c => c.Id, c => c.CreatedAt, c => c.UpdatedAt));
```

With many timestamp members, a wildcard is shorter:

```csharp
DeepAssert.Equal(expected, actual, o => o.Ignore("Id", "*At"));
```

**Expression or name?**

| | `Ignore(c => c.Id)` | `Ignore("Id")` |
|---|---|---|
| Checked by the compiler, survives renames | yes | no |
| Applies to | `Id` declared on `Customer` only | every member named `Id`, on any type |
| Wildcards (`*At`, `Audit*`, `*Temp*`) | no | yes |
| Type-qualified (`"Order.Id"`) | built in | yes |

A nested expression such as `c => c.ShippingAddress.City` ignores `City` on every `Address` in the graph. `City` on other types is still compared.

## 2. Ignore a whole nested type

Audit trails and metadata objects often differ in every field. Skip them wherever they appear:

```csharp
DeepAssert.Equal(expected, actual, o => o.IgnoreType<AuditTrail>());
```

## 3. Check a mapping or API response against an anonymous object

`DeepAssert.Equivalent` compares objects of different types by member name. The expected value is often an anonymous object, so you do not need to declare a DTO just for the test:

```csharp
var dto = CustomerService.ToDto(customer);

DeepAssert.Equivalent(new { Name = "Jacob", Email = "jacob@example.com", City = "Hanoi" }, dto);
```

The **expected** object decides what is checked. Members that exist only on the actual object are not compared, so you can check just the parts you care about, including nested ones:

```csharp
DeepAssert.Equivalent(new { Name = "Jacob", ShippingAddress = new { City = "Hanoi" } }, customer);
```

Every member of the expected object must exist on the actual object. A typo therefore fails the test instead of passing silently:

```text
Assert.Equal() Failure: 1 expected member does not exist on CustomerDto (call IgnoreMissingMembers() to skip them)
  - Nmae
```

If the expectation is shared between types that do not all have every member, add `o => o.IgnoreMissingMembers()`.

## 4. Compare query results whose order is not guaranteed

Without an `ORDER BY`, a database can return rows in any order. Compare the collections as unordered:

```csharp
DeepAssert.Equal(expected, CustomerService.LoadLines(), o => o.IgnoreCollectionOrder());
```

When the items have a natural key, match them by that key instead. If a paired item differs, the failure then names the member that differs (for example `[Sku:PEN].Quantity`) rather than just saying an item was not found:

```csharp
DeepAssert.Equal(expected, CustomerService.LoadLines(), o => o.MatchCollectionItemsBy<OrderLine>(l => l.Sku));
```

Composite keys work too: `MatchCollectionItemsBy<OrderLine>(l => l.Sku, l => l.Warehouse)`.

## 5. Accept rounding and clock differences

```csharp
DeepAssert.Equal(expected, actual, o => o
    .WithDoubleTolerance(1e-9)              // double and float
    .WithDecimalTolerance(0.01m)            // decimal
    .WithDateTimeTolerance(TimeSpan.FromSeconds(1)));  // DateTime and DateTimeOffset
```

Each tolerance is the largest accepted absolute difference. Date comparisons have millisecond resolution.

## 6. Relax string comparison

```csharp
DeepAssert.Equal(expected, actual, o => o
    .IgnoreCase()
    .IgnoreLeadingTrailingWhitespace()
    .TreatNullAndEmptyStringAsEqual());
```

## 7. Look for an item in a collection

`Assert.Contains` relies on `Equals`. The `DeepAssert` versions compare items deeply instead:

```csharp
DeepAssert.Contains(new OrderLine { Sku = "BOOK", Quantity = 1, UnitPrice = 12.50m }, lines);
DeepAssert.DoesNotContain(new OrderLine { Sku = "BOOK", Quantity = 2, UnitPrice = 12.50m }, lines);
```

They accept the same options as the other assertions. For example, this finds the line with a given SKU and ignores its other members:

```csharp
DeepAssert.Contains(new OrderLine { Sku = "PEN" }, lines, o => o.CompareOnly(l => l.Sku));
```

## 8. Plug in custom equality for one type

```csharp
DeepAssert.Equal(expected, actual, o => o
    .WithComparer<Address>((a, b) => string.Equals(a.City, b.City, StringComparison.OrdinalIgnoreCase)));
```

The comparer replaces the deep comparison for every `Address` in the graph. The type is matched exactly, so derived types are not affected. The delegate is never called with `null`: two `null` values are equal, and a `null` and a non-null value are not.

## 9. Share one set of options across tests

The configuration callback is an ordinary `Action<DeepAssertOptions<T>>`, so you can store it once and reuse it:

```csharp
private static readonly Action<DeepAssertOptions<Customer>> IgnoreGenerated =
    o => o.Ignore(c => c.Id, c => c.CreatedAt, c => c.UpdatedAt);

[Fact]
public void Reuse_options()
{
    DeepAssert.Equal(first, second, IgnoreGenerated);
}
```

There is deliberately no global or static default configuration. xUnit.net runs test classes in parallel, and shared mutable settings would make tests affect each other.

## 10. Use any other CompareNETObjects setting

`Configure` gives you the underlying [`ComparisonConfig`](https://github.com/GregFinzer/Compare-Net-Objects/wiki/Configuration). Your callbacks run after every other option:

```csharp
DeepAssert.Equal(expected, actual, o => o.Configure(config =>
{
    config.TypesToIgnore.Add(typeof(List<OrderLine>));
    config.CompareStaticProperties = true;
}));
```
